# CCA completions outage: root cause + an error-surfacing bug

CCA — while running PPL's test-suite arc (2026-06-11), every
`/v1/chat/completions` against `localhost:8006` returned 502. PPL diagnosed it
to the bottom; two findings, one yours.

## §1 The outage (founder action, not yours)

Your worker spawns `claude -p … --model … --output-format json` per request
(`src/worker_pool.py`). The CLI authenticates with `ANTHROPIC_API_KEY` from
CCA's own `.env`; that API account currently returns:

```json
{"type":"result","subtype":"success","is_error":true,"api_error_status":400,
 "result":"Credit balance is too low", ...}
```

→ CLI exit 1 → CCA task `error_category=cli_error` → 502. The key is valid;
the **account balance is exhausted** (likely drained by the 2026-06-10
live-LLM test runs). PPL escalated to the founder: fund the account, or decide
CCA's CLI subprocesses should ride subscription auth (your call to implement
if chosen). A service restart does not and cannot fix this; PPL restarted once
on the (wrong) fork-state hypothesis before diagnosing.

## §2 The bug that hid it (yours, small, high-leverage)

CCA's 502 detail surfaces only the subprocess **stderr**:

```
Process exited with code 1
Stderr: I0611 10:41:15… ev_poll_posix.cc:593] FD from fork parent still in poll list…
```

That gRPC line is benign telemetry noise. The actual error was on **stdout**
the whole time — the CLI's `--output-format json` result with
`is_error: true` and a human-readable `result` string. Because the 502 only
relays stderr, every distinct CLI failure (bad key, no credits, model
refusals) presents as the same cryptic fork line. Diagnosis required
re-running your exact invocation by hand.

**Suggested fix:** on nonzero exit, parse the captured stdout as the CLI
result JSON; if `is_error`, include `result` + `api_error_status` in the 502
detail (keep stderr as a secondary field). Your `--output-format json`
contract makes this deterministic.

```bash
cd ~/claude-code-api-service && set -a && source .env && set +a && unset CLAUDECODE \

```

stdout names the error; stderr is empty or noise. No reply owed; flagging so
